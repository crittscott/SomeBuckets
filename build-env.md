## Current IDE run configurations

`.idea/runConfigurations/` holds six configs, generated by
`architectury { platformSetupLoomIde() }` in `forge/build.gradle` and `fabric/build.gradle` and
re-synced via Gradle whenever Loom config changes:

- `Minecraft Client (:forge)` / `Minecraft Server (:forge)` — Forge dev launch, routed through
  Architectury's `TransformerRuntime` (Forge has no bare variant).
- `Minecraft Client (:fabric)` / `Minecraft Server (:fabric)` — Fabric dev launch through the same
  Architectury transformer.
- `Fabric Client (:fabric)` / `Fabric Server (:fabric)` — Fabric Loom's own plain dev launch
  (`net.fabricmc.devlaunchinjector.Main`), without the Architectury transform.

There is no data-gen or GameTest run config in this set — neither is wired into Loom's IDE run
generation for this project, matching [as-built.md](as-built.md)'s note that no Gradle GameTest or
data run is configured.

## Known environment traps

- **Compile-only deps used by `common` don't propagate to loaders.** Architectury's `common`/
  `shadowBundle` configurations carry `common`'s *compiled output*, not its dependency
  declarations. `jsr305` (for `javax.annotation.Nullable`) is redeclared as `compileOnly` in both
  `forge/build.gradle` and `fabric/build.gradle` for this reason — Forge happens to get it
  transitively anyway, Fabric does not. Adding a new compile-only library to `common` means adding
  it to every loader module too, or that loader's compile will fail without any obvious link back
  to `common`.
- **No loader may depend on `common` as a runtime project dependency** — only through the
  Architectury `common`/`shadowBundle` configurations. `implementation project(":common")` would
  double-bundle or break the per-platform transform.
- **No `buildSrc` and no dependency locking.** All version pins live in the root
  `gradle.properties`; there's nowhere else to check for an overriding version.

## Build commands

Standard wrapper invocations from the repo root; no global Gradle/Loom install is used or needed
(none is present on this machine — `gradle -v` fails, only the wrapper works):

```
./gradlew build          # both loaders
./gradlew :forge:build
./gradlew :fabric:build
```
